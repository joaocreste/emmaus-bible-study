# Internationalisation — English, Português (Brasil), Español, Français

The whole app — interface, chat engine, curated studies, Bible versions and reference formats — works in four languages. The reader picks a language in the top bar; the Bible version list then shows that language’s versions (at least three each).

## 1. Languages & Bible versions

`src/i18n/locales.ts` (`Locale = 'en' | 'pt' | 'fr' | 'es'`) and `src/domain/translations.ts` (`BIBLE_VERSIONS`).

| Language | Versions (default first) | Reference style |
|---|---|---|
| English | BSB, KJV, WEB | Romans 8:28 |
| Português (Brasil) | Bíblia Livre (BLIVRE, CC BY), Nova Bíblia Viva (NBV, CC BY-SA), Bíblia Portuguesa Mundial (BPM, PD draft) | Romanos 8:28 |
| Español | Reina-Valera 1909 (RVR1909, PD), Santa Biblia libre para el mundo (BLM, PD), Versión Biblia Libre (VBL, CC BY-SA) | Romanos 8:28 |
| Français | Louis Segond 1910 (LSG, PD), Darby (DARBY, PD), néo-Crampon Libre (NCL, CC BY-SA), Ostervald (OST, PD) | Romains 8.28 |

First visit: the browser language decides (`initialSettings`). Switching language keeps the current version if it is in that language, otherwise selects the language’s default (`withLocale`).

## 2. Interface strings

- Catalogs live in `src/i18n/messages/<namespace>.ts`, declared with `defineMessages({ en, pt, fr, es })`. **English defines the keys; TypeScript rejects any locale that misses or adds a key.**
- Components: `const t = useT('welcome'); t('headline')`; formatting helpers from `useI18n()` — `ref(passage)`, `verse(v)`, `number(n)`, `list(items)`, `date(ts)`. Never call `formatRef` without a locale in UI code.
- Engine/server (no React): `translator(locale, 'engine')`, `formatRef(ref, style, locale)`.
- Message syntax: `{name}`, `{count, plural, one {# verse} other {# verses}}`, `{x, select, a {…} other {…}}`.
- Key naming: dotted, grouped by component: `header.badge.curated`, `nav.scripture`, `empty.noCommentary`.
- No string concatenation of translated fragments — use whole sentences with placeholders (word order differs between languages).
- Accessibility text (aria-labels, titles, visually-hidden text) is translated too.
- `<html lang>` follows the locale (`LOCALES[locale].bcp47`).

## 3. Scripture references

`src/domain/bookNames.ts` holds book names, abbreviations and aliases for pt/es/fr. `formatRef(ref, style, locale)` uses them (fr uses “8.28”). `parseReference(text, {locale})`, `findReferences(text, {locale})`, `findBook(token, locale)` and `findBookMention(text, locale)` understand all four languages (accents optional; “Jó” vs “Jo” resolved in Portuguese by exact-accent match first).

## 4. Curated content

English study modules remain the source of truth (ids, references, citations). Translations are **overlays**: `src/data/curated/i18n/<locale>/<id>.ts` default-exporting a `StudyOverlay` or `TopicOverlay` (`src/data/curated/i18n/types.ts`), merged by `localizeStudy` / `localizeTopic`. The curated repository serves `list/get/findByPassage/findByTopic(…, locale)`.

Translation rules (theological content):
- **Brazilian Portuguese**, **Spanish** (neutral Latin-American/peninsular-compatible), **French** (standard); use the established theological vocabulary of each language (pt: graça, justificação, santificação, propiciação, adoção, aliança; es: gracia, justificación, santificación, propiciación, adopción, pacto; fr: grâce, justification, sanctification, propitiation, adoption, alliance).
- Never change references, ids, citations, sources or lexical data. Strong’s numbers, lemmas and transliterations stay as they are.
- Titles of works stay as cited (e.g. *Knowing God*) — never invent a translated title.
- **Verified quotations are never rewritten.** Their English words stay verbatim; an overlay may add `quoteTranslation`, rendered as “Tradução livre — não verificada” / “Traducción libre — no verificada” / “Traduction libre — non vérifiée”.
- Scripture words quoted inside prose must match the wording of that language’s **default** version (BLIVRE / RVR1909 / LSG), or be paraphrased without quotation marks.
- Key-word **anchors** for the language’s versions must occur verbatim in that verse’s text (checked by the i18n completeness test against `public/data/bible/<version>/`).
- Concept `aliases` and `matchTopics` add lowercase phrases readers of that language will type (“o que significa condenação”, “graça”, “romanos 8”).
- Search **tags** stay in English in the modules; `src/data/curated/i18n/tags.<locale>.ts` maps every English tag to the words a reader of that language would type (“doubt” → “dúvida”, “duvidar”), and the translations are appended to each item’s `tags` when a study or topic is localized (`withLocalTags`) — except cross-references, which keep ranking by concept and English tags so a question pins the same cards as in English. A test fails when a curated tag has no translation.
- The study header shows “Traduzido do inglês” (etc.) for translated curated studies.

### Authors

`src/data/registry/i18n/authors.ts` translates every author of the registries (base, shared, knowledge-base, confessions) and of the curated studies and topics, keyed by id: `name`, citation `shortName`, `tradition`, `description`, and `lifespan` when the English one carries words (“b. 1946” → “n. 1946” / “né en 1946”; French circa is “v.”).
- Church Fathers, medieval doctors, reformers and ancient writers get their conventional names (Agostinho de Hipona / Agustín de Hipona / Augustin d’Hippone; João Calvino / Juan Calvino / Jean Calvin); modern people keep their own (John Wesley, Timothy Keller, C. S. Lewis).
- Descriptions are faithful translations — no new facts; established titles of classical, patristic and confessional works are translated (Confissões, Contra las herejías), modern titles stay as cited.
- Display code calls `localizeAuthor(author, locale)` / `citationAuthorName(author, locale)` (`src/domain/attribution.ts`); English returns the registry object unchanged. The engine’s `personName` falls back to the registry by English name.
- Localized names and each entry’s `aliases` are added to the registry’s chat aliases (`findAuthor`: “o que Agostinho disse”, “¿qué dijo Calvino?”) — except bare surnames of names that stay in English, which could belong to another author.
- `src/data/registry/i18n/__tests__/authors.test.ts` fails when an author lacks a complete pt/es/fr entry, a translation drops a year or Greek word, a lifespan keeps English abbreviations, or a localized name does not resolve.

## 5. What stays in English (for now)

Open datasets that exist only in English — Tyndale study notes and introductions, Calvin/Henry/JFB/K&D commentaries, STEPBible lexicon glosses and definitions, Easton’s/Smith’s dictionaries, confessions — are shown in English with a small “(em inglês)” / “(en inglés)” / “(en anglais)” marker. Live-composed pages (inference layer) are written in the reader’s language from that English evidence; quotations stay verbatim in their original language.

## 6. Tests

- TypeScript enforces catalog completeness.
- `src/domain/__tests__/i18n-reference.test.ts` — parsing/formatting in four languages.
- `src/data/curated/i18n/__tests__/completeness.test.ts` — every curated study and topic has a complete overlay in pt/es/fr; anchors verified against the local texts.
- Engine: follow-up intents and replies in each language.
- e2e: switching language changes the interface, version list, references and study text.
